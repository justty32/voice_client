# 東西放哪、能寫什麼

回 [org](README.md)。

## 東西放哪

照順序問，第一個答「是」的就是位置。

### 產品與規矩

| 問題 | 位置 |
|---|---|
| 是產品程式碼、測試、CODE_MAP？ | dev 的地盤（[dev 卡](dev/README.md)） |
| 是產品文件、工作流、計畫、報告？ | docs 的地盤（[docs 卡](docs/README.md)） |
| 講誰管哪塊、下一棒給誰？ | `wf/org/`（只放入口和卡） |
| 講一種工作怎麼做？ | 專案的 `workflows/`（docs）；通用 kernel 補充包 `wf/workflows/`（窗口） |
| 是 aos 設定或 aos 本身的問題？ | `wf/aos/`（窗口） |

### 活狀態、紀錄與暫存

| 問題 | 位置 |
|---|---|
| 是座位的筆記、草稿、長期產出？ | 筆記 `wf/temp/{agent 名}/notes.md`；長期產出放自己的地盤（CHOICE 7） |
| 是一次調查、計畫、審查的紀錄？ | `plans/`、`reports/`、`workflows/feature-dev/landed/`（docs） |
| 是還沒做完的事？ | `SESSION-LOG.md`；只有窗口寫，其他人寫在信裡 |
| 是給使用者的題目？ | 經窗口在對話裡問；要使用者親手驗證的記 `WAIT_USER.md`（窗口寫） |
| 是可丟的東西：log、跑出來的輸出、複本？ | `wf/temp/{agent 名}/`（不進版控，隨時可清） |

只有要留下來的進 `wf/`。還在動的東西（進度、等使用者的題）不放 `wf/org/`。

## 寫入範圍是約定

每張卡寫了座位能寫什麼、只能讀什麼。這是約定，不是牆：所有 agent 是同一個帳號，檔案工具接受任何絕對路徑，shell 哪裡都去得了。拿掉一個工具不等於設了限制。

描述一條限制時，說清楚是哪一層擋的：

1. **卡或 system text 的文字**：agent 照做才算數。本組織的地盤劃分全在這層。
2. **工具裡的檢查**：用那支工具的人擋得住，旁邊開 shell 擋不住。目前沒有。
3. **作業系統**（沙箱、資源上限）：真的擋得住。目前沒有。

要寫別的座位地盤，先寫信給那個座位。

## 開座位

- **什麼時候開**：這件工作有自己的地盤，而且有規矩要活過一件工作。兩樣都沒有，就是單件工作，不是座位。
- **怎麼開**：`cp -r wf/org/seat wf/org/{座位}`，填滿四節，在座位表加一列；定義照 [wf/aos](../aos/README.md) 做。開座位是新工作，要使用者先同意。
- **細切**：使用者 2026-11-23 說「之後再細切」。從 dev 或 docs 切出新座位時，原座位的卡同一次改動拿掉那塊地盤。
- **關座位**：一次改動拿掉表上那列和卡，commit 訊息寫清楚地盤交給誰。

## 定義指向卡

座位的 system text 只說：你是哪個座位；開工前先讀 `AGENTS.md`、[org 入口](README.md)、你的卡、你的筆記；卡和 system text 衝突時聽卡。職責與地盤只寫在卡上一次。起點文字是 aos 範本 `templates/orgs/basic/extras/system.seat.txt`，已填進 `wf/aos/defs/{座位}/system.txt`。

單工不讀卡；[helper 卡](helper/README.md)是寫給派它的人看的。
