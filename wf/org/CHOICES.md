# 九個選擇

回 [org](README.md)。

每個組織只在這九處不同。選項沒有對錯，每個選項後面寫它適合什麼情況。答案寫在 **Ours:** 後面並標來源：「使用者 2026-11-23」＝使用者親口定或「3.都照推薦」認可的窗口推薦；「（提案）」＝起草時補的細節，使用者還沒確認。其他檔寫 `CHOICE n` 的地方照這裡填。

## 1. 窗口用什麼身體？

- **coding CLI（eca）**：有 CLI 自己的工具、能看圖、能開自己的子 agent。窗口要讀很多碼或看圖時選它。
- **agent-fsm**：只有給它的 aos 工具，經 llm kernel 問腦。工作只有文件和信、工具要少時選它。

**Ours:** eca：Claude Code（eca-claude 身，Opus 5.5），agent 名 `main`，在子 daemon `repo-vc`（使用者 2026-11-23）。

## 2. 座位一直掛著嗎？

- **一直掛著，退了就重起**：工作一直來、座位之間常來回時選它。
- **有工作才掛**：座位＝卡＋筆記；沒掛時窗口派代班，代班先讀卡和筆記，收工前寫回。工作斷斷續續時選它。
- **一批一掛、做完拆掉**：每批都要使用者點頭、不想帶上一批記憶時選它。

**Ours:** 有工作才掛；收工 stop、不 rm，下次接著用；座位重起時先讀卡與筆記（使用者 2026-11-23）。

## 3. 座位怎麼切？

- **按能寫什麼切**：一個座位管一塊地盤，兩個座位不寫同一個檔，沒有只負責轉手的座位。
- **按工作階段切**：設計、施工、審查、測試、整合。每個改動都要過同一條檢查線時選它。

**Ours:** 按地盤切，兩座（使用者 2026-11-23：「2.a，之後再細切。」）。

- `dev`：產品程式碼（`core/ app_wiring/ protocol/ modules/ speech/ llm/ domain/ ui/ mobile/ utils/ static/ prompts/ server_sample/`、根層 `*.py`、`config.ini`、`requirements.txt`）、`tests/`、`workflows/common/code-map/`（CODE_MAP 隨程式碼同步）。
- `docs`：`docs/`、`README.md`、`workflows/`（code-map 除外）、`plans/`、`reports/`。
- 窗口：`SESSION-LOG.md`、`WAIT_USER.md`、`wf/org/`、`wf/aos/`、`AGENTS.md`／`CLAUDE.md`／`WORKFLOWS.md`／`INDEX.md` 的路由句。

雜活（lint、搬檔、對帳）不開座位，窗口派單工（使用者 2026-11-23）。上面沒列到的路徑（`ai_assist/`、`DEV-GUIDE.md`、`models/`、`wf/` 其餘）歸窗口，要動先問（提案）。

## 4. 誰 commit？

- **只有一個關卡座位 commit**：配按階段切。
- **各座位在自己地盤內 commit，事後回報**：要出地盤、刪檔、動到跑著的 agent 時先問窗口。配按地盤切。
- **只有窗口 commit**：共用檔本來就只有一個寫手時選它。

**Ours:** 各座位在自己地盤內 commit，只 add 明確路徑（不用 `-A`），事後回報窗口；出地盤、刪檔、動到跑著的 agent 先問窗口（使用者 2026-11-23）。push：可以隨意 push（使用者 2026-11-23：「可以隨意push」）。

## 5. 不是做事的人怎麼檢查？

- **常設審查座位**，每個改動都過。
- **每批一個檢查者**，跟寫的人不同實例，讀來源不讀寫手的自述；最多 N 輪，之後停下告訴使用者。
- **窗口看證據**；要第二雙眼時另派一件單獨的工作。

**Ours:** 窗口看證據；動到 Python 時 `.venv/bin/python -m pytest -q` 全綠是硬門檻；大改另派一個不同實例的檢查者讀來源；同一處 3 輪不過停下問使用者（使用者 2026-11-23）。

## 6. 遇到不是你做的改動怎麼辦？

- **地盤外的照常；地盤內的停下問窗口**：多個座位同時在一個 checkout 工作時選它。
- **交接書沒列的一律停下問**：寫錯代價高、同時工作的 agent 少時選它。

**Ours:** 地盤外的陌生改動照常；自己地盤內出現陌生改動停下問窗口；不 revert 別人的改動（使用者 2026-11-23；與 AGENTS.md 規則 1「既有修改屬於使用者」一致）。

## 7. 暫存與座位筆記放哪？

- **暫存**：版控外的夾，隨時可清；要留的搬進工作區。
- **筆記**：不常駐的座位要有一份筆記，下一個坐上來的人先讀。
- **長期產出**：放 `wf/org/{座位}/assets/`，或放座位自己的地盤。二選一。

**Ours:** 暫存與筆記放 `wf/temp/{agent 名}/`（已在 `.gitignore`），筆記檔 `wf/temp/{agent 名}/notes.md`；長期產出放座位自己的地盤（使用者 2026-11-23）。筆記寫目前的請求、做到哪、未解的題（提案）。

## 8. 座位可以開下屬、閒時改進自己嗎？

- **不可以**：只有窗口開 agent。
- **可以，照規矩**：下屬只拿這件事要的工具；請求寫明可讀寫的範圍；回信說開了誰、做了什麼、已經收掉。改進只來自做過至少兩次的事。

**Ours:** 可以開下屬，模型隨意（使用者 2026-11-23：「agent可以再派agent做事，模型隨意。」），但腦只有 llm kernel 的 gpt 系包可選（使用者 2026-11-23：「只使用fsm gpt系列」）。下屬只拿該件事要的工具，不給能擴權的工具（`subagent`、`def` 兩包與 `self_tools`）；每份交接書寫死下屬上限（預設 2），配額往下不倍增（使用者 2026-11-23）。`fork` 出的分身也算一隻（提案）。閒時自我改進：不做（使用者 2026-11-23）。

## 9. 定義放哪、是不是複本？

- **放哪**：放 org 旁邊、放 aos 設定夾，或不放：幾個座位共用一份 stock 範本，只有卡不同。
- **複本或連結**：連到 stock 程式的定義小、跟著 aos 更新；完整複本不會變，但要手動更新。

**Ours:** 放 `wf/aos/defs/{座位}/`，動態連結 stock agent-fsm 的格程式，照 aos `templates/start-api/agents/ann` 的做法，aos 更新時跟著走（使用者 2026-11-23）。做法與檢查指令見 [wf/aos](../aos/README.md)。system text 以 aos 範本 `system.seat.txt` 為底寫成繁中，只寫「你是哪個座位、先讀哪幾份、卡與本文不一致時聽卡」與硬規則；職責只寫在卡上。
